## 학습 목표

- Spring Initializr(`spring init`)로 멀티 프로젝트 그레이들 빌드를 만든다
- product / recommendation / review 핵심 서비스와 product-composite 복합 서비스를 구현한다
- api·util 공통 모듈과 전역 예외 처리(`GlobalControllerExceptionHandler`)를 이해한다
- WebTestClient 기반 자동화 테스트와 `test-em-all.bash`로 수동 테스트를 실행한다

## 이 장의 기술

`Spring Boot`, `WebFlux`, `WebTestClient`, `Gradle 멀티 프로젝트`

## 실행하기

**3-1. Spring Initializr로 만든 골격** (`Chapter03/1-spring-init`)

```bash
cd Chapter03/1-spring-init
./gradlew build
```

**3-2. 기본 REST 서비스** (`Chapter03/2-basic-rest-services`): 서비스 4개를 직접 띄우고 테스트합니다.

```bash
cd Chapter03/2-basic-rest-services
./gradlew build
for s in product recommendation review product-composite; do
  java -jar microservices/$s-service/build/libs/*.jar &
done
./test-em-all.bash
kill $(jobs -p)   # 끝나면 서비스 종료
```

## 원본(Boot 3.5 / Java 24)과 달라진 점

- Java 24 → 21
- Gradle 래퍼 8.14 → 8.14.6
- create-projects.bash
- 테스트 스타터 추가 (Boot 4 모듈화)

- `server.error.*` → `spring.web.error.*`
- `HttpStatus.UNPROCESSABLE_ENTITY` → `UNPROCESSABLE_CONTENT`

## 복습 질문

**Q1. api 모듈과 util 모듈을 나눈 이유는?**

<details><summary>답 보기</summary>

서비스 사이에 공유하는 API 인터페이스·DTO(api)와 공통 기능(util: 예외 처리, 서비스 주소)을 한곳에 두어 중복을 줄이기 위해서다.

</details>

**Q2. product-composite는 핵심 서비스가 404를 돌려주면 어떻게 처리하나?**

<details><summary>답 보기</summary>

`ProductCompositeIntegration`이 HTTP 오류를 `NotFoundException` 등으로 바꾸고, `GlobalControllerExceptionHandler`가 같은 상태 코드의 JSON 오류로 응답한다.

</details>

**Q3. 이 저장소에서 422 상태 코드를 가리키는 상수는?**

<details><summary>답 보기</summary>

`HttpStatus.UNPROCESSABLE_CONTENT`. Spring Framework 7에서 `UNPROCESSABLE_ENTITY`에서 이름이 바뀌었다.

</details>
