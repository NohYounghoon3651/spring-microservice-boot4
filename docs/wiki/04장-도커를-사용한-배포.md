## 학습 목표

- 마이크로서비스를 도커 이미지로 만든다(레이어 추출을 쓰는 Dockerfile)
- `docker compose`로 전체 시스템을 기동하고 테스트한다
- `docker` 스프링 프로필로 컨테이너 환경 설정을 분리한다

## 이 장의 기술

`Docker`, `Docker Compose`, `Spring 프로필`

## 실행하기

**도커 컴포즈로 실행** (RabbitMQ)

```bash
cd Chapter04
./gradlew build
docker compose build
./test-em-all.bash start stop
```

## 원본(Boot 3.5 / Java 24)과 달라진 점

- Spring Boot 3.5.0 → 4.0.9
- Java 24 → 21
- Gradle 래퍼 8.14 → 8.14.6
- create-projects.bash
- 테스트 스타터 추가 (Boot 4 모듈화)
- `@AutoConfigureWebTestClient` 추가
- Jackson 2 → Jackson 3
- `catch (IOException)` → `catch (JacksonException)`
- DTO 필드의 `final` 제거
- `server.error.*` → `spring.web.error.*`
- Dockerfile: 베이스 이미지와 레이어 추출
- `HttpStatus.UNPROCESSABLE_ENTITY` → `UNPROCESSABLE_CONTENT`

## 복습 질문

**Q1. Dockerfile을 두 단계로 나누고 레이어를 추출하는 이유는?**

<details><summary>답 보기</summary>

의존성처럼 잘 바뀌지 않는 부분을 별도 레이어로 두어, 애플리케이션 코드만 바뀌었을 때 이미지 빌드와 전송을 빠르게 하기 위해서다.

</details>

**Q2. `docker` 스프링 프로필은 무엇을 바꾸나?**

<details><summary>답 보기</summary>

컨테이너 환경에 맞게 포트와 다른 서비스의 호스트 이름(서비스 이름) 등을 바꾼다.

</details>

**Q3. `test-em-all.bash start stop`은 무엇을 하나?**

<details><summary>답 보기</summary>

도커 컴포즈로 시스템을 띄우고, 전체 테스트를 실행한 뒤 시스템을 내린다.

</details>
