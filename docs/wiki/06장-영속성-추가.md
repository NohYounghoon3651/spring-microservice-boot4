## 학습 목표

- MongoDB(product, recommendation)와 MySQL(review)에 데이터를 저장한다
- MapStruct로 API 모델과 엔티티를 변환한다
- Testcontainers로 실제 데이터베이스를 띄워 영속성 테스트를 작성한다

## 이 장의 기술

`Spring Data MongoDB`, `Spring Data JPA (Hibernate 7)`, `MapStruct`, `Testcontainers 2`

## 실습 코드

- 코드: [`Chapter06`](https://github.com/NohYounghoon3651/spring-microservice-boot4/tree/main/Chapter06)
- Boot 4 변경 내역: [`Chapter06/MIGRATION-BOOT4.md`](https://github.com/NohYounghoon3651/spring-microservice-boot4/blob/main/Chapter06/MIGRATION-BOOT4.md)

## 실행하기

**도커 컴포즈로 실행** (RabbitMQ)

```bash
cd Chapter06
./gradlew build
docker compose build
./test-em-all.bash start stop
```

## 복습 질문

**Q1. product·recommendation과 review가 다른 데이터베이스를 쓰는 이유는?**

<details><summary>답 보기</summary>

서비스마다 데이터를 독립적으로 소유하고, 문서형(MongoDB)과 관계형(MySQL) 저장소를 모두 다뤄 보기 위해서다.

</details>

**Q2. 엔티티에 `@Version` 필드를 두는 이유는?**

<details><summary>답 보기</summary>

낙관적 잠금으로 동시 수정 충돌을 감지하기 위해서다(영속성 테스트의 낙관적 잠금 검사).

</details>

**Q3. Testcontainers를 쓰면 무엇이 좋은가?**

<details><summary>답 보기</summary>

테스트 중에 실제 MongoDB·MySQL 컨테이너를 띄워 운영과 같은 데이터베이스로 영속성 코드를 검증할 수 있다.

</details>
