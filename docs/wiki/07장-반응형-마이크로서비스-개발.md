## 학습 목표

- 논블로킹 동기 API(WebFlux, 반응형 MongoDB)와 블로킹 JPA 코드를 섞어 쓰는 방법을 익힌다
- Spring Cloud Stream으로 이벤트 기반 비동기 서비스를 구현한다(RabbitMQ / Kafka)
- 파티션, 재시도, 데드 레터 큐를 구성한다

## 이 장의 기술

`Project Reactor`, `Spring Cloud Stream 5`, `RabbitMQ`, `Kafka`

## 실습 코드

- 코드: [`Chapter07`](https://github.com/NohYounghoon3651/spring-microservice-boot4/tree/main/Chapter07)
- Boot 4 변경 내역: [`Chapter07/MIGRATION-BOOT4.md`](https://github.com/NohYounghoon3651/spring-microservice-boot4/blob/main/Chapter07/MIGRATION-BOOT4.md)

## 실행하기

**도커 컴포즈로 실행** (RabbitMQ)

```bash
cd Chapter07
./gradlew build
docker compose build
./test-em-all.bash start stop
```

**Kafka / 파티션 구성**

```bash
COMPOSE_FILE=docker-compose-kafka.yml ./test-em-all.bash start stop
COMPOSE_FILE=docker-compose-partitions.yml ./test-em-all.bash start stop
```

## 복습 질문

**Q1. review 서비스의 JPA 호출은 반응형 코드에서 어떻게 처리하나?**

<details><summary>답 보기</summary>

블로킹 호출을 별도 스케줄러(`jdbcScheduler`)에서 실행해 이벤트 루프 스레드를 막지 않는다.

</details>

**Q2. 생성·삭제를 이벤트로 처리할 때 장점과 대가는?**

<details><summary>답 보기</summary>

호출한 쪽이 핵심 서비스의 장애와 지연에 덜 묶이지만, 결과가 바로 반영되지 않는 최종 일관성을 감수해야 한다.

</details>

**Q3. 데드 레터 큐(DLQ)는 언제 쓰이나?**

<details><summary>답 보기</summary>

재시도 후에도 처리하지 못한 메시지를 따로 보관해 나중에 분석·재처리할 수 있게 한다.

</details>
