## 학습 목표

- 쿠버네티스의 핵심 개념(파드, 디플로이먼트, 서비스, 네임스페이스)을 익힌다
- minikube로 로컬 클러스터를 만들고 간단한 배포를 해 본다

## 이 장의 기술

`Kubernetes`, `minikube`, `kubectl`

## 실습 코드

- 코드: [`Chapter15`](https://github.com/NohYounghoon3651/spring-microservice-boot4/tree/main/Chapter15)
- Boot 4 변경 내역: [`Chapter15/MIGRATION-BOOT4.md`](https://github.com/NohYounghoon3651/spring-microservice-boot4/blob/main/Chapter15/MIGRATION-BOOT4.md)

## 실행하기

```bash
cd Chapter15
./gradlew build
docker compose build
./test-em-all.bash start stop      # 14장과 같은 시스템을 도커 컴포즈로 확인
```

쿠버네티스 첫 실습 매니페스트는 `kubernetes/first-attempts`에 있습니다(minikube 필요).

## 원본(Boot 3.5 / Java 24)과 달라진 점

- Spring Boot 3.5.0 → 4.0.9
- Java 24 → 21
- Spring Cloud 2025.0.0 → 2025.1.4
- Gradle 래퍼 8.14 → 8.14.6
- create-projects.bash
- 테스트 스타터 추가 (Boot 4 모듈화)
- `@AutoConfigureWebTestClient` 추가
- 테스트 애너테이션 패키지 변경
- TestRestTemplate 패키지 변경 및 `@AutoConfigureTestRestTemplate`
- 유레카 서버 헬스 테스트 수정
- Testcontainers 2.0
- Jackson 2 → Jackson 3
- `catch (IOException)` → `catch (JacksonException)`
- DTO 필드의 `final` 제거
- `server.error.*` → `spring.web.error.*`
- 원본 오타 수정
- MongoDB 프로퍼티 `spring.data.mongodb.*` → `spring.mongodb.*`
- springdoc-openapi 2.8.6 → 3.0.3
- Dockerfile: 베이스 이미지와 레이어 추출
- 헬스 API 패키지 변경
- `spring-boot-starter-webclient` 추가
- `spring-boot-starter-restclient` 추가 (유레카 클라이언트)
- 게이트웨이 액추에이터 엔드포인트
- OAuth2 리소스 서버 스타터
- 인가 서버 스타터 이름 변경
- 인가 서버 설정 클래스 패키지 변경
- 시큐리티 테스트 스타터
- `spring-boot-starter-aop` → `spring-boot-starter-aspectj`
- Resilience4j 2.3.0 → 2.4.0
- `ObservationRegistryCustomizer` 패키지 변경
- 분산 추적(OpenTelemetry + Zipkin) 의존성
- Zipkin 프로퍼티 이름 변경
- datasource-micrometer 1.0.0 → 2.2.1
- `HttpStatus.UNPROCESSABLE_ENTITY` → `UNPROCESSABLE_CONTENT`
- Jackson 3의 enum 직렬화
- StreamBridge 출력 바인딩을 기동 시점에 생성
- 실행 안정성 보강 (원본에도 있던 타이밍 문제)
