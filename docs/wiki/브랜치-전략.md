# 브랜치 전략

이 저장소는 **Git Flow**를 따릅니다. 자세한 규칙과 명령은 [CONTRIBUTING.md](https://github.com/NohYounghoon3651/spring-microservice-boot4/blob/develop/CONTRIBUTING.md)에 있습니다.

```text
main      ●────────────────●──────────────●        (v1.0.0, v1.1.0 … 태그)
           \              ↗ \            ↗
release     \        ●──●    \    hotfix ●
             \      ↗         ↘          ↘
develop  ●────●──●──●──────────●──●───────●
              ↖     ↖
feature        ●─●   ●─●   (feature/<이슈>-…, docs/<이슈>-…)
```

| 브랜치 | 내용 |
|---|---|
| `main` | 릴리스된 검증본. 학습은 이 브랜치나 최신 릴리스 태그로 하는 것을 권장 |
| `develop` | 다음 릴리스에 들어갈 변경을 모으는 브랜치 |
| `feature/*`, `fix/*`, `docs/*` | 이슈 하나당 하나. 이름에 이슈 번호를 넣고 PR 본문에 `Closes #번호` |
| `release/<버전>` | 전체 CI와 쿠버네티스 검증을 통과하면 `main`에 병합하고 태그 |
| `hotfix/<버전>` | `main`의 긴급 수정. 병합 후 `develop`에도 반영 |
| `original-boot3` | 교재 원본(Boot 3.5 / Java 24) 코드. 비교용 |

## 학습자를 위한 사용법

- 실습은 `main`(또는 [릴리스](https://github.com/NohYounghoon3651/spring-microservice-boot4/releases) 태그)을 받아서 하세요.
- 내 실습 내용을 남기고 싶다면 포크한 저장소에 `study/chXX` 브랜치를 만들어 작업하면, 원본 코드와 비교하기 쉽습니다.

```bash
git clone https://github.com/NohYounghoon3651/spring-microservice-boot4.git && cd spring-microservice-boot4
git switch -c study/ch13 main
```
